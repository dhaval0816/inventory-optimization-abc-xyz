# `data/clean/` - Model-Ready Demand Layer

Output of the Power Query pipeline documented in [`../../powerquery/power_query_steps.md`](../../powerquery/power_query_steps.md). These two files are the handoff between the data layer and the model layer: `weekly_demand_long.csv` feeds Power BI, `weekly_demand_wide.xlsx` feeds the Excel workbook.

Both are derived - delete them and they rebuild identically from the raw source, because every step is deterministic and documented.

---

## `weekly_demand_long.csv` - the fact grid

Exported from the `Fact_WeeklyDemand` table of the Power BI model. All 500 SKUs it shares with the Excel workbook match the workbook's `Weekly_Demand` sheet cell for cell (500 × 52 weeks, 0 differences).

**Grain:** one row per SKU per week. Shape: 3,775 SKUs × 52 weeks = 196,300 rows.

| Column | Type | Description |
|---|---|---|
| `StockCode` | Text | Product code, trimmed and uppercased. Primary key with `WeekStart`. |
| `WeekStart` | Date | Monday of the ISO week. 52 values, 2010-12-06 → 2011-11-28. |
| `Units` | Whole number | Units sold that week. `0` where there was no sale - see the zero-fill note below. |
| `Revenue` | Decimal | `Σ(Quantity × Price)` for that SKU-week, GBP. `0` where there was no sale. |

**Why the zero-fill matters.** Only 96,033 of the 196,300 rows (49%) come from an actual transaction. The other 100,267 rows are manufactured zeros - weeks in which the SKU sold nothing. They are added deliberately, because standard deviation calculated only on weeks with sales measures the variability of *selling weeks*, not the variability of *demand*, and understates σ on exactly the intermittent items whose safety stock depends on it most.

If this file is ever regenerated, the row count must be 196,300 and every `StockCode` must appear exactly 52 times. Anything else means the grid did not complete.

## `weekly_demand_wide.xlsx` - the Excel model input

**Grain:** one row per SKU. Shape: top 500 SKUs by annual revenue (67.5% of portfolio revenue) × 52 week columns.

Produced by duplicating the long query, filtering to the top 500, then Transform → Pivot Column on `WeekStart` with `Units` as values and Don't Aggregate, and merging the SKU attributes back in.

| Column | Type | Source | Description |
|---|---|---|---|
| `SKU` | Text | Real | `StockCode` |
| `Description` | Text | Real | Most frequent description for that code |
| `Category` | Text | Derived | Whole-word keyword rule on Description (Bags, Lighting, Kitchen, Cards/Gifts, Other) |
| `Unit Cost (assumed)` | Currency | Simulated | Median selling price × 0.60 (40% assumed gross margin) |
| `Lead Time weeks (simulated)` | Whole number | Simulated | `INDEX({2,4,6,8}, MOD(first 5 digits of SKU, 4) + 1)` |
| `On Hand (simulated)` | Whole number | Simulated | Deterministic rule on the SKU code → weeks of cover → `ROUND(avg weekly × cover, 0)` |
| `W1` … `W52` | Whole number | Real | Units sold in each of the 52 weeks, zeros included |
| `Median Sell Price` | Currency | Real | Median selling price over the 52 weeks, the basis for unit cost |

**Column order matters.** The workbook's `Weekly_Demand` sheet expects exactly this order starting at row 5, pasted as values. Inserting or reordering a column breaks every downstream formula reference on `SKU_Policy`.

> **Three columns in this file are simulated, not observed.** `Unit Cost`, `Lead Time (weeks)` and `On Hand` do not exist in the UCI source. Each is generated by a published, deterministic rule so that anyone re-running the pipeline gets identical values. They are labelled as simulated here, on the `Assumptions` sheet of the workbook, in the report footer, and in [`../../docs/assumptions.md`](../../docs/assumptions.md). Never quote a figure derived from them without carrying the label.

## Reconciliation between the two files

| Check | Expected | Why it matters |
|---|---|---|
| `weekly_demand_long.csv` row count | 196,300 | Grid complete |
| Distinct `StockCode` in long | 3,775 | No SKU lost in the zero-fill join |
| Rows per `StockCode` | exactly 52 | No week lost |
| `weekly_demand_wide.xlsx` rows | 500 | Excel scope |
| `SUM(W1:W52)` per SKU in wide | = `SUM(Units)` for that SKU in long | The pivot did not aggregate or drop anything |
| Wide SKUs ⊂ long SKUs | 500 of 3,775 | Excel scope is a strict subset - this is what makes the reconciliation on page 6 of the report possible |

The 500 SKUs shared between the two files are exactly the population used for the Excel ↔ Power BI validation in [`../../docs/validation.md`](../../docs/validation.md).
